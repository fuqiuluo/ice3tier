import { Steps, Tabs, TabItem } from '@astrojs/starlight/components'

The controller keeps networks, nodes and all settings in a PostgreSQL database. There are two ways to install it: with Docker, which brings its own PostgreSQL, or with the install script and a PostgreSQL of your own.

<Steps>

1. **Install.** On the server:

   <Tabs syncKey="controller">
     <TabItem label="Docker">
       ```sh
       curl -fsSLO https://raw.githubusercontent.com/fuqiuluo/ice3tier/main/deploy/docker/compose.yaml
       echo 'I3T_PUBLIC_ADDR=<public-address>:20331' > .env
       docker compose up -d
       ```

       This starts the controller together with its PostgreSQL. Run the `docker compose` commands of the later pages in the same directory.
     </TabItem>
     <TabItem label="Install script">
       The script does not install PostgreSQL: you need a database, version 16 or newer. To create one on the same machine, on Debian or Ubuntu:

       ```sh
       sudo apt-get install -y postgresql
       sudo -u postgres psql -c "CREATE ROLE i3t LOGIN PASSWORD '<password>'" \
         -c "CREATE DATABASE i3t OWNER i3t"
       ```

       Its connection string is `postgres://i3t:<password>@127.0.0.1/i3t`. Then install the controller:

       ```sh
       curl -fsSL https://raw.githubusercontent.com/fuqiuluo/ice3tier/main/deploy/install.sh |
         sh -s -- --controller --public-addr <public-address>:20331 \
           --database-url postgres://<user>:<password>@<host>/<database>
       ```

       The script installs `i3t-controller` and `i3tctl` into `/usr/local/bin`, creates the systemd service `i3t-controller` (its own system user, started at boot) and starts it. It writes the connection string to `/var/lib/i3t-controller/database.url`, readable only by the service's user.

       The connection to the database is not encrypted: keep the database on the same machine or on a trusted private network.
     </TabItem>
   </Tabs>

   `<public-address>` is the IP address or domain name nodes use to reach this machine. It is written into every enrollment token, so choose one that will not change. With a domain name you can move the controller to another machine later.

2. **Save the admin token.** It is printed once, on the first start:

   <Tabs syncKey="controller">
     <TabItem label="Docker">
       ```sh
       docker compose logs controller
       ```
     </TabItem>
     <TabItem label="Install script">
       The script prints it at the end.
     </TabItem>
   </Tabs>

   ```
   Admin token (shown only once):

       <admin-token>
   ```

   The web UI and `i3tctl` sign in with it, and it is not shown again. If you lose it, see [Lost admin token](../../maintain/admin-token/).

3. **Check the service.**

   <Tabs syncKey="controller">
     <TabItem label="Docker">
       ```sh
       docker compose ps
       ```
     </TabItem>
     <TabItem label="Install script">
       ```sh
       systemctl status i3t-controller
       ```
     </TabItem>
   </Tabs>

4. **Create a network.**

   <Tabs syncKey="admin">
     <TabItem label="Web UI">
       The web UI listens on `127.0.0.1:20332` of the server and speaks plain HTTP, so it cannot be opened from outside. Forward the port over SSH from your own computer:

       ```sh
       ssh -L 20332:127.0.0.1:20332 <user>@<server>
       ```

       Keep that session open, open [http://127.0.0.1:20332](http://127.0.0.1:20332), sign in with the admin token and create a network, for example `home`.
     </TabItem>
     <TabItem label="Command line">
       On the server:

       ```sh
       export I3T_ADMIN_TOKEN=<admin-token>
       i3tctl network create home
       ```

       With Docker, `i3tctl` is inside the controller's container. Write every `i3tctl` command of these pages like this:

       ```sh
       docker compose exec controller i3tctl --token <admin-token> network create home
       ```
     </TabItem>
   </Tabs>

</Steps>

## Docker settings

The settings are in the `.env` file next to `compose.yaml`:

| Setting | Meaning |
| --- | --- |
| `I3T_PUBLIC_ADDR` | Required: the address nodes use |
| `I3T_VERSION` | Version to run, without `v`, for example `0.1.35`. Default `latest` |

The image is `ghcr.io/fuqiuluo/ice3tier-controller` (linux amd64 and arm64), with `i3t-controller` and `i3tctl` in it. TCP and UDP 20331 are published on all addresses, the web UI's port 20332 only on `127.0.0.1` of the server. The database has no password to set and does not listen on the network: it listens on a Unix socket in a volume that only the two containers mount.

The data is in two named volumes: `postgres` holds the database, `controller` the controller's key and the cache of update packages. A third one, `postgres-socket`, holds only that socket.
