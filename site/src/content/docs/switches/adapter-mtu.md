节点的虚拟网卡上，一个 IP 包最长多少字节。

| 设置 | 默认 | 范围 | 位置 |
| --- | --- | --- | --- |
| 默认 MTU | 1280 字节 | 576 – 1500 | 网络 → 虚拟网卡 |

用命令行改：

```sh
i3tctl network set --vnet-mtu 1400
```

保存之后，节点收到就把虚拟网卡重装一遍，不用重启。

一台机器可以设自己的，改完重启节点：

```sh
sudo i3t set mtu 1200
```

设了别的值的机器不跟着网络的默认值变；写回 1280，就又跟着网络。

## 原理

应用不用管 MTU：两端的内核按它决定 TCP 的每个包带多少数据；比它大的包，内核自己切开，或者告诉发的一方"太大"。

虚拟网卡上的一个 IP 包，在节点之间是连接上的一个数据报。一个数据报装得下多少，看底下的线路：连接刚建立时是一千一百多字节，路径 MTU 探测完之后是一千三百多。装不下的包，节点切成两片发，对端拼回去。

1280 的包在探测完之后整个装得下，这是默认值的来历。

## 怎么选

- 默认的 1280 适合绝大多数线路，不用动。
- **调大**（最多 1500）：每个包带的数据多一点。但超过一千三百多之后，每个满包都要切成两片，线上的包数翻倍，反而慢。
- **调小**：底下的线路包长特别小、1280 的包一直在切的时候才值得。小到一千一百多就不用切了，代价是每个包少带一成数据。

两个节点设得不一样也通：TCP 按小的那一头来。
