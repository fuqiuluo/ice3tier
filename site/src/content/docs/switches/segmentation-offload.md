Linux 节点的虚拟网卡和内核之间，一次交接一大块数据，不是一个个的包。

| 设置 | 默认 | 位置 |
| --- | --- | --- |
| 分段卸载 | 开 | 网络 → 虚拟网卡 |

用命令行改：

```sh
i3tctl network set --vnet-offload off
```

保存之后，节点收到就把虚拟网卡重装一遍，不用重启。

一台机器可以自己关掉，改完重启节点：

```sh
sudo i3t set offload off
```

网络的开关和这台机器的开关都开着，才用。

## 原理

本机的程序经虚拟网卡发数据时，内核先把数据切成一个个不超过 MTU 的包，再一个一个地交给节点。对端来的包，节点也得一个一个地写回内核。每个包一次系统调用，内核里收和发的路每个包走一遍。

打开之后两个方向都成块地走：

- **发**：内核把最长 64 KB 的一大块直接交给节点，节点自己切成包、补上校验和。默认的 MTU 下，一块是五十来个包。
- **收**：同一批到的、同一条连接上首尾相接的包，节点先合成一大块，再交给内核一次。

线上走的包和不开时一样，对端看不出区别，所以两头不用都开。

## 什么时候起作用

- 只有 Linux 上有。Windows 和 macOS 上开关怎么设都一样。
- 看内核给不给。TCP 的成块交接各个版本都有；UDP 的要 Linux 6.2 以上，更早的内核只对 TCP 起作用。内核不给时，节点自己退回一个包一个包地交接。
- 包要来得够密。线路慢、流量小的时候，一批里只有一个包，没有可合的。

## 打开的意义

- **CPU 是瓶颈的路径快得多。** 局域网、同机房、CPU 弱的设备上，同样的流量少用很多 CPU，吞吐能高出一倍。
- 线路是瓶颈的时候（家用宽带、跨地域的线路），吞吐和延迟没有变化。

## 代价

- 合包用的缓冲占几兆内存。有包要合的时候才分配。
- 一条流把很快的线路跑满时，排在节点里的数据比不开时多，这时同一条路上别的包（比如 ping）会慢几毫秒。

## 怎么选

默认开着，不用动。经虚拟网卡的传输卡住或者内容不对时，关掉再试一次，看是不是它。
